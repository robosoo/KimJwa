STEP 01 · 시험 전체 흐름

10시부터 14시까지, 무엇이 진행될까?

먼저 과제 작업 180분과 서술형 6문항 × 5분이 다른 단계라는 것만 이해하면 돼. 질문 생성 대기 시간까지 포함해 14:00 이전에 끝내야 해.

09:40권고 접속 시각 (입장 마감 아님)
180분과제 풀이 최대
14:00모든 단계 종료
  1. 개인 링크 접속·규정 동의·감독 연결웹캠·전체 화면 공유·Proctor 연결을 먼저 준비해.
  2. ‘과제 시작’ 클릭 → 타이머·녹화 시작그 뒤 신분증과 안경 확인을 진행해.
  3. README 읽기 → Codex 개발 → 직접 검증최대 180분. 제출 미리보기 중에도 시간은 흐른다.
  4. 제출 확정 → 질문 생성 대기일반 안내 약 5분, 상세 화면에는 예상 최대 10분·재시도 가능성이 있다.
  5. 서술형 6문항 직접 작성 → 완료 확인각 5분, AI·복사 붙여넣기 금지. 14:00에 전체 종료.
09:40에 늦으면 입장할 수 없나?

09:40은 미리 접속해 준비하라는 권고 시각이야. 늦게 접속하더라도 14:00 종료 시각은 바뀌지 않으므로 남은 전체 시간이 줄어들어.

180분 + 30분이면 13:30에 무조건 종료되나?

아니야. 개인 시작 시각, 제출 시각, 질문 생성 대기에 따라 달라져. 10:00 시작→13:00에 과제 제출→5분 준비→13:05부터 30분 답변이라면 13:35 완료는 계산 예시일 뿐 보장된 종료 시각이 아니야.

식사·화장실·재접속은?

식음료는 화면과 감독 카메라를 가리지 않는 조건을 확인해. 자리 이탈 규정은 당일 09:50 별도 이메일을 확인해야 해. 재접속·문의 중에도 타이머가 멈추지 않아.

공식 근거: 시험 필수확인사항 브리프 p.1 · 사전 체험·응시환경 상세 가이드 pp.1–5

STEP 02 · 장비와 감독

감독 연결에서 가장 많이 헷갈리는 순서

PC 웹캠과 휴대폰 Cofa Proctor는 다른 장치야. 한 장치로 서로 대신할 수 없어.

  1. PC에서 개인 링크 → 규정 끝까지 읽고 동의최신 Chrome 또는 Edge, 컴퓨터·모니터 한 대, PC 웹캠 준비.
  2. 웹캠 권한 → 전체 화면 공유탭이나 창이 아닌 ‘전체 화면’을 공유. 얼굴 전체와 양쪽 귀가 보여야 해.
  3. 휴대폰 설치 QR → 연결 QR설치용은 휴대폰 기본 카메라, 응시 연결용은 Proctor 앱에서 스캔. PC에서 연결 완료 확인.
  4. ‘과제 시작’ 뒤 본인 확인녹화가 시작된 후 휴대폰을 세로 거치하고 실제 신분증·안경을 확인해.
15분 사전 체험은 1회 별도 제공돼. README 열기, 터미널에서 Codex 확인, Browser 연결, 감독 상태 및 서술형 전환을 우선 체험해. 실제 평가에는 반영되지 않아.
휴대폰 촬영 각도는 어떻게 잡을까?

앉은 자세에서 한쪽 팔을 옆으로 뻗어 손끝이 닿는 책상 위에 세로로 거치해. 전면 카메라에 얼굴·손·키보드·모니터가 보이도록 높이와 각도를 확인하고 충전선을 연결해.

권장 휴대폰·인터넷 사양

안내의 권장 사양은 iPhone 11 이상/iOS 16 이상, 또는 Android 11 이상/RAM 4GB 이상, 여유 공간 1GB 이상이야. 업로드·다운로드 각각 5Mbps 이상도 권장 속도이지 명시된 합격 커트라인은 아니야.

신분증에서 가려야 할 곳
실물 신분증가리기보이기
주민등록증번호 뒤 7자리, 주소사진·이름·생년월일
운전면허증번호 뒤 7자리, 면허번호 전체, 주소, 암호일련번호사진·이름·생년월일
여권여권번호, 하단 MRZ 두 줄, 기재된 주민번호 뒤 7자리사진·이름·생년월일·유효기간

모바일 신분증은 사용할 수 없어. 개인 신분증 이미지는 이 사이트에 업로드하지 않아.

응시 공간과 촬영 규정

혼자 있는 독립된 공간, 조명, 충전선, 알림 차단을 점검해. 투명한 문·유리벽·창문은 가려야 해. 앱 연결 자체가 녹화 시작은 아니며, 실제 과제 시작 버튼을 누르면 녹화가 시작돼.

STEP 03 · 웹 IDE·Codex

README를 먼저 읽고, Codex를 켜기

시험에서 사용자의 일은 요구사항을 이해하고 AI가 만든 결과를 판단하는 것이야. Codex는 코드를 도와주지만 최종 확인은 직접 해야 해.

실제 명령 실행이나 AI 호출은 없는 순서 연습이야.

Codex에 처음 보낼 말

“README.md를 읽고 해야 할 일, 필수 제출물, 예외조건, 모호한 업무 요구를 구분해 줘. 아직 코드는 수정하지 마.” 이는 시험 주최 측의 지정 프롬프트가 아니라 연습용 예시야.

승인 대기·실행 중·완료는 무엇이 다를까?

승인 대기는 실행할 명령을 확인해 허용·거절해야 하는 상태, 실행 중은 결과를 기다리는 상태, 완료는 Codex 요청을 끝낸 상태야. ‘완료’가 프로그램 검증이나 시험 제출 완료를 뜻하지 않아.

서버 터미널을 종료하거나 Ctrl+C를 누르면?

서버 프로세스가 종료될 수 있어. Browser에서 검증하는 동안 실행 서버가 있는 터미널은 유지해. /status로 모델·권한을 확인하고 /model은 실제 도구 메뉴가 제공하는 안내에 따라 이용해. 개인 API 키를 연결할 필요는 없어.

공식 근거: 상세 가이드 pp.2–3, p.5. 가상 단계는 실제 화면과 다를 수 있어.

STEP 04 · 도구 사용 범위

GitHub·Skill·MCP는 도구일 뿐이야

필요할 때만 사용하면 돼. 도구를 많이 연결하는 게 점수나 좋은 결과를 보장하지 않아.

README 요구사항을 먼저 확인해. 자체 작업으로 충분하면 무리해서 Clone할 필요가 없어. 필요하면 공개 출처·라이선스·외부 통신 위험·과제 적합성을 확인하고, 시험 환경 안에서만 활용해야 해.

MCP를 추가하고 싶다면?

가이드에는 MCP 탭의 설정 JSON을 변경·저장하는 기능이 소개돼 있지만, 특정 MCP가 작동한다는 보장은 없어. 데이터 전송 대상, 권한, 인증, 외부 AI 연결 여부를 점검해야 해.

STEP 05 · 실행과 저장

Codex가 만들었다면, 이제 직접 작동시켜 보기

실제 과제에서 필요한 건 만들었다는 메시지가 아니라 직접 테스트한 증거야.

  1. 서버 실행터미널의 실제 포트를 읽고 서버가 계속 실행 중인지 확인.
  2. Browser 연결PORT와 URL 경로를 입력하고 원형 화살표 새로고침. 서버는 0.0.0.0 바인딩 확인.
  3. 핵심 기능 테스트입력·버튼·이동을 눌러 결과를 관찰하고 오류·예외도 확인.
  4. 파일 저장 확인저장 중/실패/외부 변경 감지와 저장됨을 구분하고 충돌 시 두 버전 비교.
가상 Browser 연결 확인

예시 서버는 포트 4173이고 URL 경로는 /야. 실제 시험 포트는 정해진 값이 아니야.

가상 서버는 실행됐다고 가정해. PORT·바인딩·경로를 확인해 봐.
파일 저장 충돌을 어떻게 처리할까?

AI나 터미널이 에디터에 열어 놓은 파일을 수정하면 ‘외부 변경 감지’가 뜰 수 있어. 외부 변경 불러오기는 디스크 내용을 가져오는 것, 현재 내용으로 저장은 에디터 버전을 반영하는 것이야. 둘 중 무조건 정답인 것은 없으니 양쪽 내용을 비교해.

파일 상태와 다른 오류

저장 중…은 저장됨이 아니야. 디스크에서 삭제됨 상태도 자동 복원된다고 단정할 수 없어. Browser에 ‘응답 없음’이 뜨면 서버 종료·실제 PORT·0.0.0.0·URL 경로 순으로 확인해.

공식 근거: 상세 가이드 pp.2–3, p.5

STEP 06 · 제출·서술형

어떤 버튼부터 되돌릴 수 없을까?

‘제출하고 문제풀기’는 미리보기, ‘제출물 확정하고 문제풀기’는 수정 불가능한 확정이야. 이 둘만은 반드시 구분해.

제출 절차 모의실습

실제 파일 업로드·제출이나 AI 질문 생성은 없고, 버튼 의미만 체험해.

작업 중 · README 필수 경로 및 저장 상태를 먼저 확인해.
  1. 미리보기표시된 파일이 전체 제출 목록은 아닐 수 있어. 아직 돌아가 수정할 수 있어.
  2. 제출물 확정이후 파일 수정 불가. 질문 준비 대기 시작(약 5분 일반 안내·상세 최대 10분 예상 및 재시도 가능).
  3. 서술형 시작첫 문항은 ‘문제 풀기’ 클릭 순간부터 5분. 이후는 이전 답안 제출 즉시 다음 문항 5분 시작.
  4. 마지막 확인6문항 이후 ‘과제가 잘 제출됐어요’ 화면의 제출 ID·시각·파일 수·크기 확인.
후속 서술형에서는 외부 AI 및 복사·붙여넣기 금지. 각 문항은 직접 작성하고 이미 확정한 답은 수정하거나 돌아갈 수 없어. 14:00에 전체가 종료돼. 여기에는 실제 문제나 답변란을 만들지 않았어.
질문이 실제 내 작업과 다른 가정을 한다면?

질문에 담긴 전제가 틀렸다면 차이를 밝히고 본인이 실제 수행한 작업·검증 결과를 설명하면 돼. 구현하지 않은 기능을 했다고 주장하면 안 돼.

공식 근거: 브리프 p.1 · 상세 가이드 pp.3–5

STEP 07 · 장애·최종 확인

오류가 생겨도 바로 전체 새로고침하지 마

어떤 영역이 멈췄는지 먼저 찾고 그 영역만 복구하는 게 우선이야. 복구나 신고 중에도 타이머는 계속 흐를 수 있어.

감독 경고 ≠ 즉시 탈락. 확인된 제한 위반과 추가 사실관계 확인이 필요한 정황을 구분해. 경고 확인 버튼을 눌러도 기존 녹화 기록은 삭제되지 않아.
문제 신고했으면 시험 시간이 보상될까?

자동 보상은 없어. 신고만으로 타이머가 멈추거나 연장되지 않고, 플랫폼의 모델·API 장애에 대한 재응시 여부는 추후 공지 대상이야. 본인의 과도한 프로세스 사용에 따른 OOM은 구제 대상이 아니라고 안내돼 있어.

비활성·긴급 문자·서술형 오류

비활성 안내는 ‘계속 작업’으로 복구하지만 타이머는 유지돼. 휴대폰 알림·연결 이상이 있으면 원래 거치 위치를 유지하며 장치를 점검해. 서술형 화면에는 별도 신고 버튼이 없을 수 있어 오류 발생 시각·문항 번호를 기록하고 공식 절차를 이용해.

마지막으로 기억할 단 하나의 순서

환경 확인 → README → 업무 담당자 질문 → Codex 작업 → Browser 검증 → 파일 저장 → 제출 확정 → 서술형 직접 작성 → 완료 화면 확인. 이 흐름을 익혔다면 별도의 반복 퀴즈를 풀지 않아도 돼.
