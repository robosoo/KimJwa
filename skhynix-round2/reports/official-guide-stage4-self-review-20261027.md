## 공식 규정 반영
1. 일반적으로 공개된 GitHub 저장소·Skill·MCP·Plugin·소스코드·알고리즘 활용: 조건부 가능. 출처 B p.5.
2. Git Clone·다운로드로 자료를 가져오기와 Git Push로 외부 전송하기를 명확히 구분. Push 금지. B p.5.
3. 개인 PC의 비공개 Skill·파일 업로드 불가. B pp.3,5.
4. 외부 브라우저 직접 접근 제한 및 플랫폼 내 AI를 통한 공개 자료 활용. B p.5.
5. 외부 모델 연결, 문제·파일·작업 결과물 외부 전송, 제한 우회, Computer Use 자동 조작 금지. A p.1; B p.5.
6. MCP 설정 JSON은 MCP 탭에서 편집·저장 가능. B p.3.
7. 특정 저장소·Skill·MCP 설치·인증·실행 성공, 구체적 배점과 점수 가산 여부는 미공개. 사전 승인 목록을 만들어 내지 않음.

- Git Clone 대 Push 방향 구분과 형식만 제시한 명령 예제.
- 공식 규정 비교 표 및 5단계 과제 해결 순서(학습 권장임을 명시).
- 상황별 객관식 12문항: 조건부 가능 4, 명시적 금지 7, 미공개 1. 모든 문항에 해설·출처 페이지 포함.
- 도구별 Codex 사전 검토 프롬프트 3종, 복사 기능.
- 체크리스트 10항목, 브라우저 로컬 저장.
- 기존 1~3단계, 7개 앵커, 홈 진입 링크 보존.

## 자체 검토에서 발견해 수정한 문제
1. 모바일 Git Clone / Push 2열 카드에 직접 지정한 인라인 너비로 좁은 화면에서 과도한 줄바꿈 가능 → 인라인 스타일 삭제, 반응형 CSS로 1열 전환.
2. 키보드로 탭 이동할 때 선택 버튼의 현재 위치를 놓치기 쉬움 → 포커스 윤곽선 추가.
3. 버튼이 비활성화되어도 모양이 구분되지 않을 수 있음 → 비활성 표시 스타일 추가.
4. 공개 도구 활용을 무조건 허용으로 오해할 위험 → '과제 관련성·시험 제한·외부 전송' 조건과 특정 도구 승인 미공개 문구 명시.
5. 위험한 외부 연동 도구를 추천한 것으로 오해할 위험 → 구체적 특정 외부 MCP를 시험 허용 도구로 인증하지 않고 통신·권한 검토 절차로 전환.
6. 개발 초보자가 Git 명령 형식을 실제 주소로 오해할 위험 → OWNER/REPO는 실존 저장소 주소가 아닌 설명용 형식이라고 명시.
