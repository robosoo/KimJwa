# SK하이닉스 AI 해커톤 2차 · 공식 가이드 7단계 자체 QA

작성일: 2026-10-27 · 검토 주체: AI 자체 검토. 실제 대회 평가위원·독립 전문가·실사용자 참여는 없었음.

## 공식 근거
- 「시험 필수확인사항 브리프」 1쪽: 10~14시 운영과 AI/감독 관련 주요 금지 사항
- 「사전 체험 및 응시환경 상세 가이드」 3쪽: Browser·저장·제출
- 같은 자료 4쪽: 후속 6문항/타이머/질문 생성·답안
- 같은 자료 5쪽: 감독 경고와 위반 확인, 기술 장애 FAQ 및 신고

## 실제 학습 구현
- 초보자용 4단계 공통 사고 프로세스: 영역 식별 → 상태 확인 → 국소 복구 → 반복시 신고
- 장치/도구별 복구 표: 단일 영역 멈춤, 웹캠, 전체 화면 공유, 휴대폰 Proctor, Codex, 터미널, Browser, 파일 저장, 재접속, 질문 생성·전송
- 장애 사례 객관식 12문항(각 3지선다): 해설 및 공식 페이지 표시
- 감독 규정 판단 8문항(확인된 위반 vs 추가 사실관계 조사): 해설과 기록 원칙
- 문제 신고 가상 템플릿 5유형. 보안 비밀정보를 입력받지 않고 미리 작성된 가상 사례만 변경
- 전체 시간 배분 가상 시작 시각 3개, 7구간 리허설, 최종 체크리스트 15개
- 긴급 문자, 비활성 상태, 문의 후 타이머, 촬영 구도 안내, 서술형 신고 버튼, 전체 새로고침 전 저장 확인 FAQ 6개 추가

## 자체 평가·실제 반영한 개선점
1. 초기 원안에 긴급 알림/비활성/재접속 중 타이머 규정 안내가 부족 → 공식 FAQ 근거로 추가.
2. 감독 경고 = 자동 탈락이라고 오해할 수 있음 → 실제로 확인된 제한 위반과 확인이 필요한 정황을 사례별로 분리, '경고 자체는 확정 아님' 반복 강조.
3. 기타 복구 예시가 무턱대고 전체 새로고침을 권할 가능성 → 영역별 다시 불러오기와 장치별 재연결 우선.
4. 신고 화면에서 실제 접수한 것으로 오해할 가능성 → 학습용 가상 시간·증상만 보여주고 실제 신고 기능 아님을 명시.
5. 미공개 보상 규정을 단정할 가능성 → 신고는 시간 정지·연장 보장 없음, 모델·API 장애 재응시 여부는 추후 공지.
6. 시험 180분과 후속 서술형 30분을 단순 합산할 위험 → 14:00 전체 종료를 세 시작 시각 계산 예시에서 강조.
7. 모바일에서 4열 흐름/2열 판단 카드 가독성 부족 위험 → 730px/520px 반응형 스타일 적용.

## 정적 검사
- 단계 앵커 7개, 기존 1~6단계 HTML 존재, 홈 바로가기 1~7단계 확인.
- Stage7 JS 구문 검사 PASS / 원래 HTML inline JS 7개 구문 검사 PASS.
- Stage7 JS가 이용하는 id 선택자가 HTML에 모두 존재.
- 최종 체크리스트 15개, 별도 장치 복구 표·FAQ 6개·상황 문제 섹션 존재.
- Stage7 코드에 외부 네트워크 fetch/XMLHttpRequest/WebSocket/sendBeacon 요청 없음.

## 모의 DOM 사용자 이벤트 검사
- 장애 대응 12/12 정답 선택 시 정상 점수 집계 → PASS.
- 감독 위반 vs 추가 확인 8/8 정답 집계 → PASS.
- 이전/다음/다시 풀기 → 점수 초기화 PASS.
- 신고 유형 변경 시 내용 변경, 가상 발행 시각 표시 → PASS.
- 시간 가정 10:00→13:00 변경 시 안내 변경 → PASS.
- 체크박스 수정 후 로컬 스토리지 체크 여부만 저장 → PASS.
- 이는 간이 DOM 시뮬레이션. 실제 모바일 Safari·키보드·스크린리더/크로스 브라우저 검증이 아님.
