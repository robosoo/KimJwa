# AI 해커톤 1차 4P 사이트 · 가상 AI 전문가 100인 리뷰 패널

검토일: 2026-10-12

## 0. 이 평가의 성격
**가상 패널 시뮬레이션입니다.** 실제 AI 전문가를 섭외하거나 자문한 결과가 아닙니다. 한 AI가 역할·전문성별 관점을 설정하여 100개의 서로 다른 리뷰 관점을 작성했습니다. 의견들은 독립적 인간 평가가 아니며, '100명 중 n명이 동의했다'거나 유효한 통계적 설문 결과가 아닙니다.
검토 대상: 2026-10-12 기준 `민좌/ai-hackathon-mock-lab`의 4P 학습 메뉴, `data/four-p-guide.json`, 객관식 64문항, AI 실습 8개, `src/index.html`, 자동 QA 및 Vercel 운영 상태.
관찰된 사실: 4P 이론 4개, 구별 퀴즈 8개, 반도체 사례 6×4=24단계, 최소 20자 입력 후 자기 답안과 예시를 비교해 다음 단계 해제. 학습 진도는 로컬에 저장되고 import/export 가능. 사이트 내부 라이브 LLM 연결은 없음. Chromium/WebKit의 iPad 해상도 QA PASS, 실제 iPad 기기 실사용 QA는 미실시.

## 3. 가상 심사위원 간 상반된 의견과 최종 선택

**충돌 A — '사이트에서 AI API를 직접 부르자' vs '보안/운영 부담을 줄이자'**: 현재 해커톤 대비 목표에선 모델 출력이 정답일 필요가 없다. 1차 권장안은 **오류가 미리 삽입된 가상 AI 응답으로 판단/수정을 연습**하고, 실제 ChatGPT는 개인 계정에서 선택적 복사·실행하도록 유지한다. 이후 필요하면 적법한 동의와 서버 키 보관을 포함한 별도 모드로 검토.
**충돌 B — '정답을 즉시 보여주자' vs '시험처럼 감추자'**: 학습 모드는 즉시 해설, 진단 모드는 먼저 독립 답을 제출하고 공개. 사용자의 목적(해설 중심 학습과 실전 구별)을 동시에 지킬 수 있다.
**충돌 C — '반도체 전문 문제를 늘리자' vs '1차는 AI 기초 역량이다'**: 현재 1차와 비교해 반도체 지식 문제를 과도하게 늘리지 않는다. 반도체는 맥락이고 채점 대상은 4P의 판단과 검증이다.
**충돌 D — '자동 채점 모델 도입' vs '채점 신뢰성 먼저'**: 자유서술을 AI가 채점하더라도 정확하다고 보장되지 않는다. 먼저 산술·경계·출처 검증 가능한 부분만 결정적 채점으로 만들고 나머지는 근거 루브릭과 자기평가로 표시.

## 4. 추천 개발 순서
1. 4P의 6개 기존 사례와 학습자 기록을 유지한다. 정답 열람과 수행 성공을 분리하는 새 결과 필드를 추가한다.
2. 실제 문제 기준 가상 AI 오답 산출물 6개를 만들어 Probe 역검증을 구현한다(원시 데이터·정답·오류 위치는 fixture로 명시).
3. Prompt 1차/2차 수정 비교 기능과 검증 근거 기록을 추가한다.
4. Plan/Prompt/Probe/Protect 완료 후 새로운 수치 1개가 자동 선정되는 '변형 미니 시험'을 제공한다. 채점 가능한 계산만 자동 판정한다.
5. Playwright 자동화+사용자 실기기 확인을 별도 로그로 구분하고 기존 Vercel 링크의 버전/데이터/4P 요소를 재확인한다.

## 5. 리뷰어별 가상 피드백 100건
아래 100건은 **가상의 역할 기반 자문**이며 실재 인물 발언이 아니다. 심각도 P0(우선 해결), P1(개선 필요), P2(확장 기능)로 정리했다.

### 가상 위원회 1 — AI 개념·모델 연구 (10명)

- **가상 전문가 001 · AI 리터러시 연구자 [P1]**: 64문항 지식 테스트는 있지만 4P 사례에서 모델 출력의 확률적 오류를 경험하지 못한다. 동일 입력에 서로 다른 답안 2개를 제시하고 신뢰도를 비교하게 하자.
- **가상 전문가 002 · LLM 시스템 연구자 [P1]**: FP01에서는 계산 가능한 행 비율과 관측 불가인 웨이퍼 비율이 명확하다. 단정 금지 대신 '답변 보류'를 성공 행동으로 반복 연습시켜야 한다.
- **가상 전문가 003 · RAG 설계자 [P1]**: FP04 사양서 리비전이 충돌할 때 검색 결과의 적용일·승인 체계를 찾아가는 단계가 짧다. 문서 검색 결과 카드 3개를 제공해 선택하도록 하자.
- **가상 전문가 004 · 불확실성 추정 연구자 [P1]**: AI 답변을 사실/가설/미확인으로 나누게 설명하지만 판정의 오류율을 따로 표시하지 않는다. 불확실성을 근거의 종류와 연결하자.
- **가상 전문가 005 · 멀티모달 연구자 [P2]**: 반도체 현장은 파형·계측 이미지·테이블 해석이 중요한데 4P 사례는 모두 텍스트다. 오실로스코프 파형의 축/단위 읽기 사례가 필요하다.
- **가상 전문가 006 · 추론 성능 연구자 [P2]**: 모델이 정답이라고 단언해도 실제로는 잘못될 수 있다. 자신감 높은 오답을 구별하는 반례 사례를 넣자.
- **가상 전문가 007 · 컨텍스트 엔지니어 [P2]**: 26개념에 컨텍스트·토큰을 배우지만 4P 실전에 자료 절제 훈련이 부족하다. 필요한 근거 파일만 고르도록 하자.
- **가상 전문가 008 · 모델 선택 전문가 [P2]**: 입문 과제에서도 고비용 모델을 쓰는 것이 이점인지 다루지 않는다. 정확성·비용·시간 기준의 모델 선택 문제를 추가하자.
- **가상 전문가 009 · AI 품질 연구자 [P1]**: '근거 있음'과 '출처가 해당 주장을 뒷받침함'은 다르다. 출처는 있어도 결론을 지지하지 않는 반례를 학습시키자.
- **가상 전문가 010 · 신뢰성 엔지니어 [P1]**: 한 번 맞힌 문제를 곧바로 숙달로 기록하면 기술 이전을 과대평가한다. 변형 문제 통과와 재시험을 구별하자.

### 가상 위원회 2 — 프롬프트·AI 협업 (10명)

- **가상 전문가 011 · 프롬프트 설계자 [P0]**: Prompt 단계에서 실제 AI 결과와 상호작용하지 않아 문장 쓰기 연습으로 끝난다. 예상 응답을 주고 오류 기반 2차 질문을 작성하게 하자.
- **가상 전문가 012 · 에이전트 UX 디자이너 [P1]**: AI가 질문을 되묻는 상황이 빠져 있다. 부족한 자료를 요청하고 사람이 제공 여부를 결정하는 분기를 만들자.
- **가상 전문가 013 · 구조화 출력 전문가 [P1]**: 출력 형식 예시가 주로 '표로 작성' 수준이다. 판정표의 필수 열·타입·상태값을 제시하는 연습이 필요하다.
- **가상 전문가 014 · 워크플로 디자이너 [P1]**: Plan의 목표에서 Prompt의 작업지시로 넘어갈 때 조건이 누락되는 오류를 추적하지 않는다. 조건 인수인계 검사를 추가하자.
- **가상 전문가 015 · 실험 설계형 프롬프트 연구자 [P1]**: 처음 프롬프트와 수정 프롬프트의 성능 차이를 비교하지 못한다. 같은 사례에서 A/B 질문안을 돌려 결과를 대조하게 하자.
- **가상 전문가 016 · Few-shot 전문가 [P2]**: 경계 조건 사례를 프롬프트에 예시로 제공하는 훈련이 없다. FP02에서 1.029/1.030/1.031 V 삼단 경계를 보여주자.
- **가상 전문가 017 · 도구 활용 설계자 [P1]**: 실습에 'ChatGPT 열기'는 있으나 검증용 계산기·표 프로그램과의 역할 분리를 가르치지 않는다. 도구별 작업 분해를 추가하자.
- **가상 전문가 018 · 요구사항 추적 전문가 [P1]**: AI에 전달한 조건의 누락을 사람과 AI가 각각 점검하도록 하지 않는다. 원요구 대비 프롬프트 체크리스트를 만들자.
- **가상 전문가 019 · 질문 전략 연구자 [P2]**: 질문 횟수를 줄이는 것 자체가 목표가 아니다. 정보 이득이 큰 후속 질문을 고르는 연습이 필요하다.
- **가상 전문가 020 · 평가용 AI 시스템 연구자 [P1]**: 정답 유도식 프롬프트가 '원인 3개'를 만들게 한다는 예제는 좋다. 숫자·원인 개수를 강제한 요청을 스스로 수정하는 연습을 강화하자.

### 가상 위원회 3 — Probe·계산·근거 검증 (10명)

- **가상 전문가 021 · LLM 평가 연구자 [P0]**: Probe가 설명형 모범 답안으로 끝난다. 먼저 의도적으로 틀린 AI 산출물을 주고 잘못된 셀과 근거를 지목하게 해야 한다.
- **가상 전문가 022 · 통계검증 연구자 [P1]**: FP03의 +2%p vs +2.5% 구분은 좋다. 표본·제품 리비전 변수를 섞어 잘못된 인과 단정을 검출하는 확장 사례가 필요하다.
- **가상 전문가 023 · 지표 검산 전문가 [P1]**: FP06 Accuracy·Recall·Precision 계산을 지식으로만 평가한다. FN 비용을 변경했을 때 판단을 업데이트하는 전이 테스트를 넣자.
- **가상 전문가 024 · 데이터 품질 전문가 [P1]**: FP01 중복 검사 단위 문제는 실제성이 높다. 고유 ID의 중복 해소 규칙에 따라 결과가 달라지는 데이터 파일을 제공하자.

- **가상 전문가 080 · 일관성 리뷰어 [P1]**: 바로 '정답'이라고 밝히는 8개 구별 퀴즈는 자기평가 편향이 생긴다. 일정 수를 푼 뒤 해설을 공개하는 시험형 분기를 추가하자.

### 가상 위원회 9 — iPad UX·접근성 (10명)

- **가상 전문가 081 · iPad 사용성 전문가 [P1]**: 가상 키보드로 답을 쓰며 4개 단계를 오가는 흐름을 실기기에서 검증하지 않았다. Safari 키보드·스크롤·포커스 실험이 필요하다.
- **가상 전문가 082 · 모바일 정보설계자 [P2]**: 4P 개념 카드→8개 분류→사례→실습이 한 화면에 길게 이어진다. 단계별 목차와 진도 표시를 고정하자.
- **가상 전문가 083 · 학습 UX 연구자 [P1]**: 한 번에 4P 24단계를 보이면 피로하다. 1회 1사례 4단계 중심의 짧은 세션이 낫다.
- **가상 전문가 084 · 접근성 전문가 [P1]**: 4P 텍스트 영역과 복잡한 동적 영역은 스크린리더/VoiceOver 실제 사용 검증이 필요하다. 브라우저 에뮬레이션만으로 충분하지 않다.
- **가상 전문가 085 · 색각 다양성 리뷰어 [P2]**: 정오답을 초록/빨강으로 표시할 때 색 외 텍스트 안내와 명도 대비가 유지되는지 확인하자.
- **가상 전문가 086 · 사용자 제어 전문가 [P1]**: 프로필 전환은 로그인 분리가 아니다. 여자친구 등 다른 학습자가 같은 기기를 쓸 때 기록 선택 안내를 강화하자.
- **가상 전문가 087 · 데이터 백업 UX 담당자 [P1]**: 학습기록 JSON 내보내기/가져오기는 있으나 실제 iPad 파일 앱으로 복구하는 안내가 부족하다. 기기간 복원 튜토리얼을 만들자.
- **가상 전문가 088 · 콘텐츠 가독성 전문가 [P2]**: 64개 문제 지문이 평균 약 389자다. iPad에서도 조건·자료·질문이 눈에 분리되는 시각적 레이아웃이 필요하다.
- **가상 전문가 089 · 오류 메시지 UX 담당자 [P1]**: 20자 제한 오류는 글 길이만 알려준다. '조건/근거/미확인' 중 무엇이 부족한지 힌트가 더 유용하다.
- **가상 전문가 090 · 동기부여 UX 연구자 [P2]**: 24/24 완료 뱃지만 강조하면 답 복사를 유도할 수 있다. 실제 검증 성공/자기 수정 횟수 등 성취 근거를 분리하자.

### 가상 위원회 10 — 소프트웨어 QA·운영 (10명)

- **가상 전문가 091 · 프론트엔드 QA 전문가 [P1]**: 현재 브라우저 스모크 검사는 주로 첫 사례의 Plan→Prompt 개방만 검증한다. 전체 4단계 완료·수정 시 재잠금·사례 전환도 검증하자.
- **가상 전문가 092 · 테스트 자동화 엔지니어 [P1]**: Chrome/WebKit 화면크기 검증은 통과했다. 그러나 실제 iPad Safari 기기와 모바일 키보드 동작 테스트는 별개로 남아 있다.
- **가상 전문가 093 · 저장상태 설계자 [P1]**: 4P 기록의 가져오기 기능이 있는 점은 좋다. 손상/구버전 JSON·중단된 입력에 대한 테스트를 추가하자.
- **가상 전문가 094 · 상태 전이 검증자 [P1]**: 이전 단계 수정 시 후속 단계 reviewed를 해제한다. 저장된 후속 답안에 무효 표시가 이해 가능한지 테스트해야 한다.
- **가상 전문가 095 · 릴리즈 엔지니어 [P1]**: Vercel READY와 외부 HTTP 검증까지 갖췄다. 다음 릴리즈에서 4P 데이터 내용/버전이 바뀌면 캐시와 기록 호환성도 검사하자.
- **가상 전문가 096 · 데이터 품질 검사자 [P1]**: 현재 64문항 수치 계산 검산은 있지만 설명의 의미 정확성을 완전하게 자동 보장하지 않는다. 기술적 리뷰를 샘플링해 추가하자.
- **가상 전문가 097 · 접근성 테스트 자동화 담당자 [P2]**: 브라우저 오류 0만으로 키보드 네비게이션·ARIA·읽기 순서까지 보장되지 않는다. axe-core 같은 규칙 기반 검사와 실제 리뷰를 병행하자.
- **가상 전문가 098 · 성능 분석가 [P2]**: 운영 HTML이 약 524KB로 전체 문제·4P 데이터를 내장한다. 저사양 iPad 초기 로드·캐시 비용을 확인하자.
- **가상 전문가 099 · 보안 QA 담당자 [P1]**: 자유서술 입력은 escape 처리되는 것으로 보인다. 다른 입력과 importData를 포함한 XSS/문자 경계 시나리오를 회귀시험에 넣자.
- **가상 전문가 100 · 데이터 분석 엔지니어 [P1]**: 외부 사용자 데이터를 수집하지 않으므로 보안 친화적이다. 실제 효과를 확인하려면 동의를 받아 익명화된 학습전후 지표를 수집하는 별도 방식이 필요하다.
